# Afield user guide

Afield is currently an invite-only personal test. Use public topics and non-confidential preferences. Your operator must configure the services and keep a worker available for new generation. An account can authenticate only after its email is admitted; registration and Google sign-in do not grant access automatically.

## Explore a question

1. Choose **Explore** and enter a specific question. Add context explaining what you want to understand.
2. Choose depth and a word or listening-time budget. Listening time is an estimate until requested audio is measured.
3. Choose **Use my sources only**, **My sources + research**, or **Search only**. Add public source URLs if your choice uses them.
4. Select each URL's reading method: exact page; RSS/Atom feed; bounded linked pages; or search within this site. A page reads only that URL; it does not automatically read the entire publication. Site search uses the search allowance and does not bypass paywalls.
5. Choose **Make my brief**, confirm the selected limit if the request contains a conflicting limit. Otherwise submission proceeds directly. Follow progress; the displayed time is provisional. If a temporary failure occurs, use the provided retry for the same run instead of repeatedly submitting a new one.
6. Read the text and linked citations. Open **Original request & source coverage** to see which sources were read, unavailable or unused in citations. A retrieved source is not necessarily a cited source. Use revision to start a changed request while keeping the original brief.

## Follow a topic

Choose **Stay updated → New topic**. Enter a name, learning goal, preferences and depth. Optional subtopics refine your interests; click chips to select/deselect. Deselected chips remain visible, and regenerating suggestions preserves selected interests. Add custom interests as needed.

Open **Manage sources**. Ask for recurring source suggestions or add a URL manually. Recommendations are checked for learning value but still need your judgment. They may return few or no results. Review the rationale and reading method, check accessibility, then explicitly choose sources to use. A suggested publication site uses a fresh search for future updates; an exact static article cannot discover future news by itself.

Choose **Templates**, copy a template if useful, change its name/tone/output length, choose blocks and reorder them. Set a daily/weekly schedule, local time and named timezone. Review the configuration and activate only when sources/settings are ready. Pause/resume governs future scheduling. Manual updates can use a different coverage mode without changing the saved schedule policy. Past briefs remain unchanged.

## Listen, revisit and manage your account

A saved brief starts as text. Press **Generate audio** only when you want narration. Reopening/replaying uses saved audio; repeated clicks share pending work, and matching verified audio can be reused within your account. A time-limited brief remains unverified until narration is measured; over-budget or failed audio is reported rather than silently changing the saved text.

Use **Overview** for recent work and **History** to find briefs by date/topic. Multiple briefs can appear on one date. Use **Personal account** to inspect shared allowance/reset times and request history; **Settings & privacy** handles export and deletion. Download audio separately if you need a complete personal backup. Deletion is pending until the worker confirms cleanup.

## When something goes wrong

| Situation | Action |
|---|---|
| No topic for suggestions | Add a topic name or goal in Settings; subtopics are optional |
| Search unavailable | Use exact public pages/feeds/linked pages or ask the operator to configure Tavily |
| Work stays queued | Ask the operator to check the local/cloud worker; saved results remain readable |
| Provider temporarily busy | Wait and use the offered retry; repeated new requests may use additional allowance |
| Partial coverage | Read the source-check explanation and citations; do not assume missing sources were considered |
| No meaningful developments | Expect a short/no-news brief only when retrieval succeeded; failures are different |
| Sign-in denied | Check invitation, verified email, exact callback setup and provider notices with the operator |
